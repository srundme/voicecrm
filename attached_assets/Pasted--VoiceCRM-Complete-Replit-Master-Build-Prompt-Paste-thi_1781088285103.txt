> Paste this entire file into Replit Agent. Build in the order specified.

## OVERVIEW

You are building a full-stack SaaS client portal called **VoiceCRM** — a Bolna AI voice call
orchestration platform with a built-in Insurance CRM, designed for Indian insurance companies.
This is a client-facing portal only (not the Bolna dashboard). All AI call intelligence happens
through Bolna's APIs; this app orchestrates, stores, and visualises everything around those calls.

---

## TECH STACK

- **Framework**: Next.js 14 (App Router), TypeScript
- **Styling**: Tailwind CSS — Brevo-inspired UI. Subtle, pleasant, frosted glass cards.
  - Primary: `#4F46E5` (indigo-600)
  - Background: `#F8FAFC`
  - Cards: `bg-white/80 backdrop-blur-sm ring-1 ring-slate-200 rounded-xl shadow-sm`
  - Accent success: `#10B981`, warning: `#F59E0B`, danger: `#EF4444`
- **Database**: PostgreSQL via Prisma ORM
- **Realtime**: Server-Sent Events (SSE) for live call status
- **Auth**: NextAuth.js with credentials provider
- **Email/SMS**: Brevo API (transactional)
- **Charts**: Recharts
- **Icons**: Lucide React
- **Job queue**: Simple in-process async queue (pg-boss optional if scale needed)

- `brevo_api_key`
- `meta_ads_access_token`
- `meta_ads_account_id`
- `webhook_secret` (auto-generated UUID on first setup)
- `context_api_bearer_token` (auto-generated, shown to user for Bolna configuration)
- `monthly_checkin_agent_id` (Bolna agent ID for monthly follow-up calls)

Create `lib/api-config.ts`:
```ts
export async function getApiConfig(): Promise<ApiConfig> {
  // always reads from DB, never cached, never hardcoded
}
```

Create `lib/bolna-client.ts`:
- All Bolna API calls go through this single file only
- Calls `getApiConfig()` on every request to get fresh keys
- If `bolna_api_key` is missing: return `{ success: false, error: "Bolna API key not configured. Go to Settings → API Config." }`

- Log all errors to console with `[BolnaClient]` prefix and include `execution_id` when available

## MODULE 4: CALL ORCHESTRATION ENGINE

File: `lib/call-engine.ts`

### triggerCallForLead(leadId, agentId, options?)

```
1. Fetch lead from DB by leadId
2. Call GET /api/call-context?contact_number={lead.phone}&agent_id={agentId}
   (call your OWN endpoint — keeps context logic in one place)
3. Spread the returned JSON as user_data.variables in the Bolna makeCall payload
4. Call bolnaClient.makeCall({
     agent_id: agentId,
     recipient_phone_number: "+91" + lead.phone,
     user_data: { variables: contextResponse }
   })
5. Save new CallLog: {
     bolna_execution_id: response.execution_id,
     bolna_agent_id: agentId,
     lead_id: leadId,
     phone_number: lead.phone,
     status: INITIATED,
     direction: OUTBOUND,
     memory_injected: contextResponse,
     call_type: contextResponse.call_type,
     retry_of_call_id: options?.retryOfCallId
   }
6. Start pollCallStatus(executionId, callLogId) as async background task
7. Return { success: true, call_log_id, execution_id }
```

### pollCallStatus(executionId, callLogId)

```
Poll getExecution(executionId) every 4 seconds.
On each poll, update CallLog.status in DB.

When status = COMPLETED:
  a. Fetch execution logs → save transcript, summary, recording_url to CallLog
  b. Update lead.last_contacted_at = now()

  c. DROP DETECTION:
     Set drop_detected = true if ALL of:
       - duration_seconds < 45
       - transcript does NOT contain any of:
         ["theek hai", "okay", "shukriya", "dhanyavaad", "goodbye", "bye",
          "interested nahi", "zaroorat nahi", "call back", "baad mein",
          "confirmed", "policy", "documents", "send karo"]
       - transcript length > 20 characters (some attempt was made)
     
     If drop_detected:
       - Save drop_reason = "short_call_no_intent_detected"
       - Schedule retryDroppedCall(callLogId) after 120 seconds

  d. CALLBACK DETECTION:
     If transcript contains any of:
       ["call back", "baad mein call", "kal call", "shaam ko", "dopahar",
        "2 baje", "3 baje", "evening", "morning", "husband se", "wife se",
        "pooch ke", "sochna hai", "time chahiye"]
     Then:
       - Create FollowUp: {
           type: CALLBACK_REQUESTED,
           scheduled_at: extractTimeFromTranscript() ?? now() + 4 hours,
           notes: "Callback requested during call " + executionId,
           bolna_agent_id: callLog.bolna_agent_id
         }

  e. Update Lead.stage:
     - If INTERESTED keywords found → INTERESTED
     - If NOT_INTERESTED keywords found → LOST (only if repeated)

When status = FAILED or NO_ANSWER after 90s: mark and stop. No retry.
When status unchanged after 10 minutes: mark as FAILED. Stop.
```

### retryDroppedCall(originalCallLogId)

```
1. Fetch original CallLog + Lead
2. Call triggerCallForLead(lead_id, agent_id, { retryOfCallId: originalCallLogId })
   — the context endpoint will detect drop_detected = true and return opening_line
3. Update original CallLog.retry_call_id = newCallLog.id
```

### scheduledFollowUpCall(followUpId)

```
1. Fetch FollowUp + Lead + Policy
2. Update FollowUp.status = IN_PROGRESS
3. Determine agent:
   - MONTHLY_CHECKIN type → use api_config.monthly_checkin_agent_id
   - Others → followUp.bolna_agent_id
4. Call triggerCallForLead(lead.id, agentId)
5. Update FollowUp: { call_log_id: newCallLog.id }
6. When call completes → FollowUp.status = COMPLETED, completed_at = now()
```

### CONCURRENCY RULES

- Every call gets its own isolated async polling loop
- Use `setImmediate` / `Promise` — never block
- Errors in one call's poll loop must NEVER affect other calls
- Maintain in-memory Map: `activePolls: Map<executionId, NodeJS.Timeout>`
- On server restart: query DB for INITIATED/IN_PROGRESS calls and resume polling

## MODULE 5: UNIFIED CONTEXT API ENDPOINT

**This is the most important endpoint in the system.**

File: `app/api/call-context/route.ts`
Method: GET
Auth: Bearer token validation against `api_config.context_api_bearer_token`

This same URL is configured in:
1. Bolna's Inbound Agent Settings → "Use Internal APIs"
2. Called by your own `triggerCallForLead()` before every outbound call

### Query params received from Bolna (and your own engine):
- `contact_number` — phone number of the caller/recipient
- `agent_id` — Bolna agent ID
- `execution_id` — unique call execution ID (may be absent for pre-call lookups)

### Logic

```
1. Validate Bearer token. Return 401 if invalid.
2. Normalise phone: strip +91, spaces, dashes → 10 digits
3. Find Lead in DB by phone (exact match on phone or phone_alt)
4. Find most recent CallLog for this lead (order by created_at DESC, limit 1)
5. Find pending FollowUp for this lead where status=PENDING and scheduled_at <= now+5min

6. Determine call_type:
   - No lead found                              → "inbound_new"
   - No CallLog exists                          → "new"
   - Last CallLog.drop_detected = true
     AND last CallLog.created_at > now - 15min  → "drop_retry"
   - Pending FollowUp of type CALLBACK_REQUESTED → "callback"
   - Otherwise                                  → "inbound_known" or "outbound_with_history"

7. Build and return JSON:
```

**Scenario: new**
```json
{
  "call_type": "new",
  "user_name": "Priya Sharma",
  "gender": "female",
  "city": "Chennai",
  "insurance_type": "term",
  "context": "",
  "opening_line": "",
  "previous_execution_id": ""
}
```

**Scenario: drop_retry**

## MODULE 6: LEAD SOURCES

### A) Meta Ads Webhook
`POST /api/webhooks/meta-leads`

```
1. Verify X-Hub-Signature-256 header using meta_ads_access_token as secret
2. Parse Meta lead form payload
3. Map fields:
   - full_name ← first_name + last_name
   - phone ← phone_number (strip +91 and spaces)
   - email ← email
   - city ← city
   - insurance_type ← custom field "insurance_type" if present
   - source_campaign_id ← campaign_id
   - source_form_id ← form_id
   - source = META_ADS
4. Create Lead in DB (skip if phone already exists for this org)
5. If automation AUTO_CALL_ON_LEAD is active for this org:
   Schedule triggerCallForLead() after 30 seconds
6. Return HTTP 200 immediately. All processing is async.
```

### B) Website Form
`POST /api/webhooks/website-form`

Accept JSON body:
```json
{
  "org_id": "xxx",
  "full_name": "string",
  "phone": "9876543210",
  "email": "string",
  "gender": "male|female|other",
  "dob": "YYYY-MM-DD",
  "insurance_type": "term|health|life|motor",
  "city": "string",
  "pincode": "string"
}
```

Validate:
- phone: 10 digits, starts with 6–9
- org_id: must exist in DB

Create lead with `source = WEBSITE_FORM`.
If automation active: schedule call after 30 seconds.
Return `{ success: true, lead_id: "xxx" }`.

Also expose `GET /api/form-embed/:orgId` which returns
a self-contained HTML form snippet clients paste on their website.
The snippet POSTs to your webhook URL with the org_id pre-filled.

### C) CSV Bulk Import
`POST /api/leads/bulk-import`

- Accept `multipart/form-data` with `file` (CSV) and `org_id`
- Parse CSV. Expected columns:
  `full_name, phone, gender, dob, email, city, state, pincode, insurance_type, notes`
- Validate each row:
  - phone: 10 digits, starts with 6–9
  - gender: male/female/other (case-insensitive)
  - Skip rows with invalid phone
- Deduplicate: skip rows where phone already exists for this org
- Batch insert valid rows (use Prisma `createMany` with skipDuplicates)
- Return:
  ```json
  { "imported": 142, "skipped_duplicates": 18, "skipped_invalid": 3, "errors": [] }
  ```
- Optional: if `trigger_calls=true` param is set, schedule calls for all imported leads

## MODULE 9: SSE REAL-TIME CALL FEED

File: `app/api/calls/live-feed/route.ts`

```
GET /api/calls/live-feed

1. Set headers:
   Content-Type: text/event-stream
   Cache-Control: no-cache
   Connection: keep-alive

2. On connection:
   - Query DB for all CallLog where status IN [INITIATED, RINGING, IN_PROGRESS]
   - Stream current state as initial event

3. Every 3 seconds:
   - Query same + any completed calls from last 30 seconds
   - Send event: data: {JSON}\n\n

4. Every 15 seconds:
   - Send heartbeat: : ping\n\n

5. On client disconnect: clear interval, close

Event payload shape:
{
  "type": "call_update",
  "calls": [
    {
      "execution_id": "xxx",
      "call_log_id": "xxx",
      "lead_name": "Priya Sharma",
      "phone": "98765 43210",
      "agent_name": "Insurance Agent Tamil",
      "status": "IN_PROGRESS",
      "direction": "OUTBOUND",
      "call_type": "new",
      "duration_seconds": 47,
      "started_at": "2026-06-10T10:30:00.000Z"
    }
  ],
  "active_count": 3,
  "timestamp": "2026-06-10T10:30:47.000Z"
}

Frontend: use EventSource API. Reconnect automatically on disconnect.
```

## CRITICAL IMPLEMENTATION RULES

1. **Never hardcode any API key anywhere.** Always read from DB via `getApiConfig()`.
2. **All Bolna calls go ONLY through `lib/bolna-client.ts`** — never call Bolna directly from a component or other file.
3. **All async operations isolated** — one call failing must never affect concurrent calls.
4. **Phone numbers**: stored as 10 digits (no prefix, no spaces). Displayed as `+91 XXXXX XXXXX`. Always prepend `+91` when sending to Bolna.
5. **All dates**: stored as UTC in DB. Displayed in IST (Asia/Kolkata). Use `Intl.DateTimeFormat` with `timeZone: 'Asia/Kolkata'`.
6. **Indian validation**:
   - PAN: `/^[A-Z]{5}[0-9]{4}[A-Z]{1}$/`
   - Aadhaar: 12 digits
   - Phone: 10 digits, starts with 6–9
   - Pincode: 6 digits
7. **Error messages**: always user-friendly. Never show raw API errors. Log details to console.
8. **On server restart**: resume polling for any CallLog with status INITIATED or IN_PROGRESS.
9. **Context API response time**: must be < 800ms. Index all lookup fields.
10. **All monetary values**: stored as integers (paise for premiums) or BigInt (sum assured). Display with `₹` and Indian number formatting.
